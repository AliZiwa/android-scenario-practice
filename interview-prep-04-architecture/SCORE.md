## Problem by problem

1. **Two Retrofits.** Fixed. One `Retrofit`, one `OkHttpClient`, one `FakePartsBackend`, all `lazy` in `AppDependencyContainer`.
2. **`Globals`.** Fixed. Deleted in commit 1 (renamed to `AppContainer`, then dissolved into `PartsBinApp` in commit 2). The offline flag is now `OfflineState`, a `MutableStateFlow` wrapper that the container owns, the fake backend reads and the list screen writes. Passing it into the screen as a parameter is fine; a `domain` package is an odd home for a toggle that exists to drive a test double, but the ADR says so and the architecture test allows it.
3. **`allowMainThreadQueries` and string navigation.** Fixed. Typed `@Serializable` routes, `toRoute<PartsDetail>()`, `popBackStack()`.
4. **Room written and never read.** Fixed. `observeAll()` is the list's source; a failed refresh leaves it alone; the message is a string the ViewModel chose, not the exception's.
5. **Detail refetches and disagrees with the list.** Fixed. `observeById(id)` is the detail's source and `adjust` writes the server's answer through `upsert`.
6. **Low stock in two places with two rules.** Half fixed. One rule (`<=`), still two places (`PartDto.toRow()` line 36, `PartEntity.toRow()` line 32). The contract says "the same rule, from the same code". Put `val lowStock get() = quantity <= minQuantity` on the domain model and delete both computed fields.
7. **Mapping written out in each ViewModel; `updatedAt` raw.** Fixed in the ViewModels, moved to the data layer, but duplicated there (see 6), and the formatted string is stored in the "domain" model. The DTO should map to the entity only; the entity maps to the domain model; formatting is a UI concern and belongs in the UI model or the composable.
8. **No repository, no domain model, no home for a rule.** Repository: yes. Domain model: a row, not a model. Home for a rule: `require(...)` in a data class, with the "Not enough stock" check reading Room (`partDao.getById(id)?.quantity ?: 0`, which means an unknown id is "Not enough stock" rather than not found). A `domain` function, `fun Part.validateAdjustment(delta: Int, reason: String): AdjustmentError?` or a sealed `AdjustmentResult`, tested on its own, is the deliverable the brief named.
9. **Errors as strings; 422 body never read.** Regressed in one way and unchanged in another. The body is now read, parsed, and then thrown away by the enclosing `catch (parseEx: Exception)`, so the user still sees "Server said 422". And the types that cross the boundary are `IllegalArgumentException(message)`, `ServerException(message)` and `IOException`, which is three exception classes carrying strings, and the ViewModel does `e.message ?: "..."`; that is strings between layers with extra steps. A sealed `AdjustmentResult { Success(part), Rejected(reason: AdjustmentError), ServerRejected(code: ServerCode), Offline }` is what "typed outcomes" means, and the ViewModel then maps each case to its message in one `when`.
10. **Nothing unit-testable.** Fixed. Both ViewModels take an interface, the repository takes a DAO and a service, and there are tests at all three.
